# 本项目多代理政策（Sol 领导 + Luna 执行）

## 角色分工

- **主会话（Sol / `gpt-5.6-sol`）**：理解需求、判断风险、拆解阶段、做架构和取舍决策、整合、独立验收、兜底。始终保留最终决策权和 commit/PR/部署控制权。
- **`luna_scout` / `gpt-5.6-luna`**：只读探索代码库、依赖、日志和文档，返回路径与事实证据。
- **`luna_worker` / `gpt-5.6-luna`**：只在任务卡明确的文件范围内实现当前阶段，禁止提交或发布。
- **`luna_critic` / `gpt-5.6-luna`**：只读对抗审查正确性、安全、回归风险和测试缺口。
- **`luna_tester` / `gpt-5.6-luna`**：按指定计划运行测试、类型检查和产物核验，报告原始证据。

## 默认委派与分流

Sol 默认将边界清晰的执行工作交给一个 Luna，尤其是涉及两个以上文件、预计超过 2 分钟、需要重复机械操作、独立测试或对抗审查的任务。单条只读命令、几行以内的单文件明确修改、纯问答和简单状态查询可由 Sol 直接完成。

| 任务 | 执行者 | 权限 | 回报重点 |
|---|---|---|---|
| 探索文件、依赖、日志、文档 | `luna_scout` | read-only | 路径、事实、命令、限制 |
| 有边界的实现、批量机械修改、模板生成 | `luna_worker` | workspace-write | 修改文件、diff、检查、数量/顺序 |
| 测试、类型检查、产物核验 | `luna_tester` | workspace-write | 命令、退出码、日志、行为 |
| 安全、回归和测试缺口审查 | `luna_critic` | read-only | 严重度、位置、依据 |
| 需求、架构、跨模块取舍、验收、外部操作 | Sol | 主会话 | 决策和闸门证据 |

## 阶段与并行

默认阶段 DAG 为：`盘点 -> 实现 -> 验证 -> Sol 验收`。审查（`luna_critic`）按需安排，不属于默认 DAG。每个阶段必须记录依赖、输入、输出、执行者、状态、闸门证据和解锁时间；前置闸门未通过不得解锁后续阶段。

默认只派 1 个 Luna。只有输入、输出、写入范围和依赖彼此独立、无共享状态和顺序要求时才并行，最多 3 个 Luna；每个并行任务必须有独立任务卡和闸门，不得让多个 worker 同时写同一文件或生成物。

## Sol 持续等待与并行执行

当已派出的子智能体存在真实运行中的任务（执行命令、安装、编译、测试或等待外部进程）时，Sol 必须持续等待到 `completed`、`failed`、`timed_out` 或 `needs_user_input`；暂时没有新输出的正常等待不判作 stalled，也不得因此提前宣称完成或中断任务。

只有所有并行任务都到达终态并经 Sol 独立验收后，才能统一输出。任一任务失败、超时、缺少关键产物或需要用户输入时，整体结果必须标记为未完成，并锁定依赖该任务的后续阶段。

## 任务卡与失败处理

每个 Luna prompt 必须包含：角色、目标、范围、输入、验收、约束和回报格式。约束至少包括不越界、不备份、不生成临时文件、不处理密钥、不提交、不发布。回报必须列出修改文件、命令与退出码、关键结果、输入输出数量、错误日志、风险和未完成项。

阶段失败时，最多向同一个 Luna 回派 2 次最小修复，并附确切失败证据和唯一修复目标。两次仍失败，由 Sol 接管最小修复或重新拆分；不得跳过闸门、伪造通过或无限重试。Luna 回报后停止，不自行推进下一阶段。

## Sol 验收

Sol 不能只相信 Luna 总结，必须独立检查实际 diff、文件范围、测试命令和退出码、错误日志、残留文件、接口调用链、错误处理、用户可见行为，以及适用时的数量、唯一 ID、索引和顺序。发现错误、缺产物或证据矛盾时停止后续阶段。

## 安全

不把 API Key、密码、私钥、主机秘密或真实凭据写入仓库、任务卡或回报。只引用环境变量名。commit、PR、部署和其他外部操作永远由 Sol 控制。
