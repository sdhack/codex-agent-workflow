# Claude Code 多代理政策

- 主会话使用最强可用模型（领导层）：规划、审核、整合、兜底。
- 执行层优先调用 `.claude/agents/` 下的 luna-* 子代理（haiku 或账号内最便宜模型）。
- 失败或质量不达标立即 escalate 回主会话。
- commit / PR / 部署永远由主会话控制。

## Sol 调度补充

若当前项目由 Codex Sol 主会话调度：默认流程为盘点 → 实现 → 验证 → Sol 验收；审查按需安排，不自动插入默认流程。真实运行中的子任务（执行命令、安装、编译、测试或等待外部进程）必须持续等待到 `completed`、`failed`、`timed_out` 或 `needs_user_input`，正常等待不判作 stalled。

输入、输出、写入范围和依赖均独立的任务最多并行 3 个；每个任务单独设置任务卡和闸门。所有任务结束且 Sol 独立验收后才统一输出；任一失败、超时、缺少关键产物或需用户输入时，整体未完成并锁定依赖阶段。
